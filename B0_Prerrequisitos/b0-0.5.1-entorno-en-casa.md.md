## 🎯 Qué se pedía

Replicar en el ordenador de casa todo el entorno de trabajo configurado previamente en el centro (Fases 0.1 a 0.4.b). Esto incluye instalar Obsidian, Git y OBS, generar una clave SSH propia para este equipo y vincularla a GitHub, y reconstruir la estructura local de la bóveda clonando los repositorios desde GitHub fuera de OneDrive.

## ⌨️ Comandos y pasos importantes

- `git --version` — Comprueba que Git se ha instalado correctamente en el equipo. 
- `ssh-keygen -t ed25519 -C "tu-correo-de-github"` — Genera un nuevo par de claves SSH (pública y privada) de tipo Ed25519 para autenticar el equipo de casa. 
- `cat ~/.ssh/id_ed25519.pub` — Muestra por pantalla la clave pública para copiarla y añadirla a GitHub. 
- `git config --global user.name "Tu Nombre"` y `git config --global user.email "tu-correo"` — Configura la identidad del autor para los futuros commits en este ordenador.
- `ssh -T git@github.com` — Verifica que la conexión SSH con GitHub funciona correctamente. 
- `mkdir -p RUTA_SOR/Boveda_SOR/00_Apuntes` y `mkdir -p RUTA_SOR/Boveda_SOR/01_Practicas` — Crea la estructura de carpetas local para la bóveda (asegurando que esté fuera de OneDrive). 
- `git clone git@github.com:jholopzam/apuntes-sor-t1.git Trimestre_1` — Clona el repositorio de apuntes renombrando la carpeta destino a `Trimestre_1` para mantener la misma estructura que en el centro. 
- `git clone git@github.com:jholopzam/bloque-0-prerequisitos.git B0_Prerrequisitos` (y lo mismo para `B1_Entorno` y `B2_Ubuntu_Local`) — Clona los repositorios de prácticas personales dentro de `01_Practicas`.

## 🤔 Respuestas a las preguntas

1. **¿Por qué clonas desde GitHub en vez de copiar con pendrive?** Porque en GitHub está alojada la versión actualizada y sincronizada del proyecto. Al clonar directamente desde el repositorio remoto, nos aseguramos de tener una copia exacta vinculada al control de versiones (con su historial y configuración remota lista para hacer `pull` y `push`), evitando pérdidas de archivos o desincronizaciones que ocurren al mover carpetas manualmente con un pendrive.
2. **¿Por qué generas una clave SSH nueva en casa?** Por seguridad y buenas prácticas: las claves privadas nunca deben copiarse ni transportarse de un ordenador a otro. Cada equipo desde el que trabajamos debe tener su propio par de claves SSH registrado en GitHub (por ejemplo, `Equipo Centro` y `Equipo Casa`), lo que además permite revocar el acceso de un ordenador concreto sin afectar a los demás si fuera necesario.
3. **¿Dónde NO debe estar la bóveda?** No debe estar dentro de carpetas sincronizadas en la nube como **OneDrive** (en Windows, la carpeta `Documentos` suele venir vinculada por defecto con el icono de la nube). Git y OneDrive entran en conflicto al gestionar los archivos internos ocultos del repositorio (`.git`), pudiendo corromper el historial o generar ficheros duplicados con el nombre del equipo (`-MiPC.md`). Debe ubicarse en una ruta puramente local dentro de `C:\Users\Usuario`.
