## 🎯 Qué se pedía
Configurar la autenticación mediante claves SSH en GitHub para interactuar con los repositorios de forma segura sin necesidad de introducir la contraseña en cada operación, comprendiendo el funcionamiento de la clave pública y privada, y conociendo la alternativa de tokens HTTPS.

---

## ⌨️ Comandos y pasos importantes
* `ssh-keygen -t ed25519 -C "correo"` — Sirve para generar el par de claves criptográficas SSH (pública y privada) utilizando el algoritmo ed25519 asociado a tu correo electrónico.
* `cat ~/.ssh/id_ed25519.pub` — Sirve para mostrar el contenido de la clave pública por pantalla para poder copiarla y añadirla a GitHub.
* `ssh -T git@github.com` — Sirve para comprobar y verificar la conexión SSH con GitHub y asegurar que la autenticación es exitosa.

## 🤔 Respuestas a las preguntas
1. **¿Cuál de las dos claves se pega en GitHub? ¿Cuál NO se comparte nunca?** 
   Se pega la clave **pública** (el fichero que termina en `.pub`), ya que actúa como el candado en el servidor. La clave **privada** (sin extensión) **no se comparte jamás**, ya que es la llave que se queda exclusivamente en tu ordenador.
2. **¿Por qué usamos SSH en vez de la contraseña?** 
   Porque las contraseñas tradicionales ya no se admiten en GitHub para estas operaciones por motivos de seguridad, y el uso de claves SSH ofrece una autenticación permanente, cómoda y robusta basada en criptografía asimétrica.
3. **Si el año que viene usas otro ordenador, ¿reutilizas la clave o creas una nueva? ¿Por qué?** 
   Se crea una **nueva** clave específica para el nuevo equipo, ya que cada dispositivo debe tener su propio par de claves independiente por motivos de seguridad y control de accesos.
