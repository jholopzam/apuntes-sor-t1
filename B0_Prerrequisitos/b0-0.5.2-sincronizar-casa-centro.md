## 🎯 Qué se pedía

Dominar el ciclo diario de sincronización en Git (`pull → trabajar → push`) entre el ordenador de casa y el del centro. Además, comprender por qué este ciclo debe realizarse por separado en cada carpeta de repositorio modificada, por qué Git y OneDrive no pueden gestionar el mismo directorio y comprobar que los cambios subidos desde un equipo se reflejan correctamente en el otro
## ⌨️ Comandos y pasos importantes

- `pwd` — Muestra la ruta del directorio actual en Git Bash para confirmar que estamos dentro del repositorio correcto (`.../Boveda_SOR/00_Apuntes/Trimestre_1`). 
- `git pull` — Descarga e integra los últimos cambios desde GitHub antes de empezar a trabajar en el ordenador. 
- `git add .` — Prepara todos los archivos nuevos o modificados en el área de staging de Git. 
- `git commit -m "Fase 0.5.2: apuntes escritos desde casa"` — Guarda los cambios preparados en el historial local con un mensaje descriptivo. 
- `git push` — Sube los commits locales al repositorio remoto en GitHub para que estén disponibles desde el otro equipo

## 🤔 Respuestas a las preguntas

1. **¿Por qué NO se mete la bóveda en OneDrive si usamos Git?** Porque son dos sistemas de sincronización distintos peleándose por los mismos ficheros. OneDrive sincroniza a medias la carpeta oculta `.git` y la corrompe, crea copias en conflicto (`fichero-MiPC.md`) y hace que el comando `git pull` pierda su sentido. La bóveda debe estar siempre en local y usar GitHub como nube. 
2. **Escribe el ciclo diario de tres pasos.** 1. **Al empezar (`git pull`):** descargar los últimos cambios desde GitHub antes de tocar nada. 2. **Trabajar (Obsidian):** editar o crear las entradas correspondientes.
3. **Al terminar (`git add .` → `git commit` → `git push`):** guardar y subir todos los cambios a GitHub antes de irse. *(Nota: Este ciclo se aplica de forma independiente en cada carpeta de repositorio que se modifique ese día).* 3. **¿Qué problema puede aparecer si olvidas el `pull` al empezar?** Puede producirse un **conflicto (`CONFLICT`)** al intentar fusionar cambios si se editó el mismo archivo en dos equipos distintos sin haber bajado antes la versión más reciente, haciendo que Git no sepa qué versión conservar.
